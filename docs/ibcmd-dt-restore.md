# Загрузка .dt в Microsoft SQL Server через ibcmd

Проверено 18 ноября 2026 года. Вывод: **ibcmd умеет загружать .dt в информационную базу 1С на Microsoft SQL Server** командой `infobase restore`. Это полная замена данных и конфигурации базы. Для обновления только конфигурации используются другие команды (`config load` / `config apply`).

## Основания

1. В официальном руководстве 1С 8.3.27, [раздел 7.4.7](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.27_Administrator_Guide/Chapter_7.Standalone_server/7.4._Examples_of_managing_and_starting_the_standalone_server/7.4.7._Import_data_from_the_export_file___.dt__to_the_infobase/?language=en), приведён пример `infobase restore` с параметрами MSSQL. В [разделе 7.4.6](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.27_Administrator_Guide/Chapter_7.Standalone_server/7.4._Examples_of_managing_and_starting_the_standalone_server/7.4.6._Create_an_infobase_from_the_export_file___.dt_/?language=en) описано создание новой SQL-базы из .dt через `infobase create --restore`. При проверке страницы перенаправляли на портал поддержки; примеры доступны в поисковом индексе.
2. В [описании изменений 8.3.20](https://dl03.1c.ru/content/Platform/8_3_20_1613/1cv8upd_8_3_20_1613.htm) подтверждены прямые параметры подключения `ibcmd` к СУБД. Без `--pid` и `--remote` утилита запускает собственный автономный сервер на время команды.
3. На рабочем компьютере проверены `ibcmd --version` и `ibcmd help infobase` для установленной **8.3.27.2214**. Локальная справка подтверждает сочетание `restore`, `--dbms=MSSQLServer`, `--db-server`, `--db-name`, `--db-user`, `--request-db-pwd` и позиционного пути к файлу выгрузки. Для MSSQL в этой справке указан запуск на Windows.

## Пример команды для существующей базы

После подготовки отдельной тестовой базы и отключения сеансов:

```powershell
& 'C:\Program Files\1cv8\8.3.27.2214\bin\ibcmd.exe' infobase restore `
    --dbms=MSSQLServer `
    --db-server='DEV-SQL' `
    --db-name='uho_ke_tk' `
    --db-user='sql_service' `
    --request-db-pwd `
    --data='D:\DevRefresh\ibcmd-data\test-job' `
    'D:\Backups\uho_ke.dt'
```

SQL-пароль поступает через STDIN. Если в существующей информационной базе настроена аутентификация 1С, дополнительно нужны `--user` и `--password` с правами администратора ИБ. Это отдельные учётные данные, отличные от SQL-логина. Способ безопасного предоставления пароля ИБ службе нужно выбрать при реализации.

`--create-database` разрешает создать отсутствующую SQL-базу. `--force` запрашивает принудительное завершение сеансов; при его использовании нужно явно задать `--session-terminate-message`, чтобы фоновый запуск не ожидал ввода сообщения. Поведение блокировок и завершения сеансов для базы, зарегистрированной в обычном кластере 1С, требует отдельной проверки. Нельзя считать, что переключение SQL в SINGLE_USER заменяет управление сеансами 1С.

## Что потребуется в DevRefresh

Это отдельный источник восстановления, для которого нужен собственный исполнитель. Текущий исполнитель `.bak` использует SQL RESTORE и не может прочитать `.dt`.

- Настройки пути к Windows-утилите 1С подходящей версии, каталога .dt и при необходимости учётной записи администратора ИБ; проверка прав службы на файлы и каталог `--data`.
- Подбор .dt по типу базы и та же проверка прав на целевую базу, включая общий список операторов `_tk`.
- Монопольный доступ к целевой ИБ, блокировка новых входов, обработка текущих сеансов и восстановление настроек доступа при завершении.
- Запуск отдельного процесса с перенаправлением STDIN/stdout/stderr, проверкой кода завершения, таймаутом и отменой. Пароли не должны попадать в журналы или описание задания.
- Предварительная резервная копия целевой базы и отдельный сценарий восстановления после сбоя: автоматический откат загрузки .dt не предполагается.
- Проверка открытия базы через обычный кластер 1С после загрузки, фоновых заданий, расширений и прав пользователей.

## Предел проверки

Поддержка команды подтверждена документацией и справкой установленного исполняемого файла. Загрузка реального .dt в SQL-базу не выполнялась. Замеры времени, совместимость конкретного дампа с платформой и работа с сеансами кластера должны проверяться на выделенной базе тестового контура. Поддержка .dt в интерфейс DevRefresh этой доработкой не добавляется.
