# Загрузка .dt через создание SQL-базы

В DevRefresh 0.2.56 используется `ibcmd infobase create --restore`, только с учётными данными MSSQL. Перед командой существующая целевая SQL-база удаляется. Временные .bak и дополнительные SQL-базы не используются.

## Почему требуется удаление

На установленной Windows-платформе **8.3.27.2214** проверено: попытка `infobase create --force --restore=...` поверх уже существующей ИБ возвращает ошибку «Информационная база с указанным именем или параметрами соединения уже зарегистрирована». После удаления этой SQL-базы создание из .dt успешно завершилось. `--force` команды create подтверждает предупреждения, а не заменяет удаление существующей ИБ.

Пример команды после удаления целевой тестовой базы:

```powershell
& 'C:\Program Files\1cv8\8.3.27.2214\bin\ibcmd.exe' infobase create `
    --dbms=MSSQLServer --db-server=DEV-SQL --db-name=bp_gm_dev_owner `
    --db-user=sql_service --request-db-pwd --create-database --force `
    --data='D:\DevRefresh\data\ibcmd\dt-job' `
    --restore='D:\BackupsDt\bp_gm.dt'
```

SQL-пароль передаётся через STDIN. Параметры `--user` и `--password` пользователя ИБ не передаются. Перед удалением DevRefresh проверяет SQL-вход IBCMD и наличие CREATE ANY DATABASE либо роли dbcreator/sysadmin. Основное SQL-подключение DevRefresh выполняет проверку базы, блокировку параллельных заданий, отключение соединений и удаление.

## Последовательность

1. Выбрать и открыть подходящий .dt, проверить версию IBCMD и SQL-права создания.
2. Удерживать SQL applock целевой базы, проверить существование и тип базы и согласие на отключение соединений.
3. Удалить целевую SQL-базу и выполнить IBCMD create с загрузкой .dt.
4. Выполнить операции для вида архива и формата .dt, затем SQL-проверки и DBCC CHECKDB по настройке.
5. Опубликовать готовность базы. Ошибка после удаления не восстанавливает прежнюю базу автоматически.

При отмене/таймауте останавливается дерево процессов. Сохраняемый вывод ограничен; SQL-пароли скрываются в сообщениях и не передаются в командной строке. [Настройка и подтверждение удаления](../deploy/portable/README.md#восстановление-из-dt-через-ibcmd).

## Проверки

Интеграционные тесты с реальным IBCMD и локальным MSSQL создают отдельную файловую ИБ, выгружают настоящий .dt, запускают штатный исполнитель DevRefresh для временной SQL-базы и проверяют успешное пересоздание. Временных .bak не появляется. Отдельный тест доказывает, что при отсутствии права создавать базы исходная SQL-база сохраняется. Каждый тест удаляет только собственные случайно именованные SQL-базы и SQL-логин.

Это проверка механики на пустой ИБ. Совместимость производственных выгрузок с версией платформы, объём свободного места, открытие через обычный кластер 1С и Windows-вход проверяются на целевом контуре. RAS/RAC не управляются: остановку фоновых заданий и новых подключений обеспечивает администратор.
