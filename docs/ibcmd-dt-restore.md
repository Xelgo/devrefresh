# Загрузка .dt в Microsoft SQL Server через ibcmd

DevRefresh 0.2.55 поддерживает `.dt` как четвёртый источник актуализации. **ibcmd загружает .dt в информационную базу 1С на Microsoft SQL Server** командой `infobase restore`. Это полная замена данных и конфигурации базы. Для обновления только конфигурации используются другие команды (`config load` / `config apply`). Исследование выполнено 18 ноября 2026 года.

## Основания

1. В официальном руководстве 1С 8.3.27, [раздел 7.4.7](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.27_Administrator_Guide/Chapter_7.Standalone_server/7.4._Examples_of_managing_and_starting_the_standalone_server/7.4.7._Import_data_from_the_export_file___.dt__to_the_infobase/?language=en), приведён пример `infobase restore` с параметрами MSSQL. В [разделе 7.4.6](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Administrator_Guides/1C_Enterprise_8.3.27_Administrator_Guide/Chapter_7.Standalone_server/7.4._Examples_of_managing_and_starting_the_standalone_server/7.4.6._Create_an_infobase_from_the_export_file___.dt_/?language=en) описано создание новой SQL-базы из .dt через `infobase create --restore`. При проверке страницы перенаправляли на портал поддержки; примеры доступны в поисковом индексе.
2. В [описании изменений 8.3.20](https://dl03.1c.ru/content/Platform/8_3_20_1613/1cv8upd_8_3_20_1613.htm) подтверждены прямые параметры подключения `ibcmd` к СУБД. Без `--pid` и `--remote` утилита запускает собственный автономный сервер на время команды.
3. На рабочем компьютере проверены `ibcmd --version` и `ibcmd help infobase` для установленной **8.3.27.2214**. Локальная справка подтверждает сочетание `restore`, `--dbms=MSSQLServer`, `--db-server`, `--db-name`, `--db-user`, `--request-db-pwd` и позиционного пути к файлу выгрузки. Для MSSQL в этой справке указан запуск на Windows.

## Пример команды для существующей базы

После подготовки отдельной тестовой базы и отключения сеансов:

```powershell
& 'C:\Program Files\1cv8\8.3.27.2214\bin\ibcmd.exe' infobase restore `
    --dbms=MSSQLServer `
    --db-server='DEV-SQL' `
    --db-name='uho_ke_tk' `
    --db-user='sql_service' `
    --request-db-pwd `
    --data='D:\DevRefresh\ibcmd-data\test-job' `
    'D:\Backups\uho_ke.dt'
```

SQL-пароль поступает через STDIN. Если в существующей информационной базе настроена аутентификация 1С, дополнительно нужны `--user` и `--password` с правами администратора ИБ. Это отдельные учётные данные, отличные от SQL-логина. Способ безопасного предоставления пароля ИБ службе нужно выбрать при реализации.

`--create-database` разрешает создать отсутствующую SQL-базу. `--force` запрашивает принудительное завершение сеансов; при его использовании нужно явно задать `--session-terminate-message`, чтобы фоновый запуск не ожидал ввода сообщения. Поведение блокировок и завершения сеансов для базы, зарегистрированной в обычном кластере 1С, требует отдельной проверки. Нельзя считать, что переключение SQL в SINGLE_USER заменяет управление сеансами 1С.

## Реализация в DevRefresh

Для `.dt` используется отдельный исполнитель, без SQL RESTORE. В настройках задаются отдельная папка архивов, папка `bin` с IBCMD, рабочий каталог, таймаут и учётные данные администратора целевой ИБ. Общий SQL-логин можно заменить отдельным логином IBCMD. При Windows-аутентификации основного SQL-подключения отдельный SQL-логин IBCMD обязателен. [Порядок настройки](../deploy/portable/README.md#восстановление-из-dt-через-ibcmd).

- Имена `.dt` разбираются по правилам `.bak`, включая дату `dd-MM-yyyy` и соответствия типов. Отложенное задание подбирает свежий файл при запуске.
- Права на базу проверяются тем же способом, включая общий список операторов `_tk`; отозванные права останавливают ожидающее задание до SQL-операций.
- Приложение удерживает общий SQL applock целевой базы на время загрузки и не запускает параллельное восстановление этой базы. При подтверждении завершения соединений передаётся `--force`. Управление блокировкой новых входов через RAS/RAC не реализовано: подготовку обычного кластера выполняет администратор.
- Отдельный процесс получает SQL-пароль через STDIN; stdout/stderr читаются параллельно с ограничением сохраняемого вывода. Настроены таймаут и остановка дерева процессов при отмене. Из известных паролей очищаются сообщения об ошибках. Пароль ИБ передаётся штатным параметром `--password` и доступен администраторам ОС в командной строке процесса; команда с аргументами не журналируется.
- Код завершения проверяется; после успеха выполняются проверка SQL-доступа и DBCC CHECKDB по общей настройке. Автоматического отката загрузки и переключения на `.bak` нет. Резервную копию целевой базы перед первым испытанием нужно подготовить отдельно.
- Версия совместимости SQLite повышена до 12: она включает защиту формата `.dt`-заданий и хранение операций после восстановления.

## Предел проверки

Поддержка команды подтверждена документацией и справкой установленного исполняемого файла. В работающем интерфейсе проверены сохранение настроек и запуск установленного IBCMD 8.3.27.2214 через кнопку проверки. Автотесты проверяют подбор архивов, права, очередь, защиту паролей, аргументы запуска, stdout/stderr, таймаут и отмену, совместимость заданий и выбор четвёртого источника. Загрузка реального .dt в SQL-базу не выполнялась. Замеры времени, совместимость конкретного дампа с платформой и работа с сеансами обычного кластера должны проверяться на выделенной базе тестового контура, включая открытие через кластер, фоновые задания, расширения и права пользователей.
